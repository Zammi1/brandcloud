# `@brandcloud/tokens`

Shared semantic colour, typography, spacing, radius, shadow and motion foundations for BrandCloud consumers, plus brand themes generated from a small JSON file, a Tailwind v4 layer, a shadcn/ui bridge and the `brand-ui-lint` checker.

Use the public package exports rather than source paths:

| Export | What it is |
|---|---|
| `@brandcloud/tokens` | Typed token module: `reference`, `semantic`, `themes`, `brands`, `metadata` |
| `@brandcloud/tokens/css` | Semantic CSS custom properties (`--brand-*`) at `:root`, default brand, light mode |
| `@brandcloud/tokens/themes.css` | Every mode (`data-theme`) and every brand (`data-brand`) |
| `@brandcloud/tokens/brands/harbour.css` | One brand on its own, at `:root` (dark under `data-theme="dark"`) |
| `@brandcloud/tokens/tailwind.css` | Tailwind v4 `@theme inline` layer and gradient utilities |
| `@brandcloud/tokens/shadcn.css` | shadcn/ui variable contract mapped onto brand roles |
| `@brandcloud/tokens/tokens` | Generated JSON token data |
| `@brandcloud/tokens/contrast-report` | Every WCAG contrast check the build ran, per brand and mode |
| `@brandcloud/tokens/ui-lint` and the `brand-ui-lint` bin | The UI lint for consumer repositories |

Consumers should deliberately map their existing variables to these semantic roles. The package is a shared foundation and is not a replacement for an application's typography, product meaning or visual identity.

## Brands and modes

Two attributes, set on `<html>` or on any element:

- `data-theme="light" | "dark" | "operator"` picks the mode.
- `data-brand="<name>"` picks the brand palette. Without it you get the neutral default palette (`brandui`).

```html
<html data-brand="harbour" data-theme="light">
  ...
  <section data-theme="dark">Still Harbour, now in its dark palette.</section>
</html>
```

```css
@import "@brandcloud/tokens/css";        /* defaults and reference values */
@import "@brandcloud/tokens/themes.css"; /* modes and brands */
```

A single-brand site can import just its brand sheet: `@import "@brandcloud/tokens/brands/harbour.css";` puts the Harbour light palette at `:root` and the dark palette under `data-theme="dark"`.

Brands cover `light` and `dark`. Nesting works both ways (a brand inside a dark page, a dark section inside a brand); for three-level nesting of different brands, put `data-brand` and `data-theme` on the same element.

### Brands in the box

| Brand | What it is | Default button |
|---|---|---|
| `brandui` (default) | Neutral starting palette, plus a warm `operator` mode for dense product screens. Replace it with your own brand. | `solid` |
| `harbour`, `orchard`, `marigold` | Fictional example brands, each generated by `make-brand` from four inputs | `depth` (marigold: `solid`) |
| `docs` | The documentation site's own brand | `depth` |

Fonts are not shipped in this package: a brand names its font stack and the site loads the font files under their own licence.

`--brand-action-appearance` (and `metadata.brands[].appearance` in JS) says which Button appearance a brand defaults to. `@brandcloud/ui`'s `button.css` applies the same default in CSS: depth under any `[data-button-appearance="depth"]` ancestor.

## Roles

All roles compile to `--brand-<role>`. Every role exists in every brand and mode.

**Surfaces and text:** `canvas`, `surface`, `surface-raised`, `surface-subtle`, `surface-muted`, `surface-interactive`, `text`, `text-muted`, `text-subtle`, `border`, `border-strong`, `accent`, `accent-hover`, `accent-text`, `accent-subtle`, `focus`, `focus-ring`, `status-*`, `danger`, `inverse-*`, `overlay-*`.

**Depth button** (a tonal gradient that models light on a physical button):

| Role | Use |
|---|---|
| `action-depth-from`, `action-depth-to` | Body gradient, lighter top to deeper bottom, same hue |
| `action-depth-glow`, `action-depth-glow-reach` | Light rising inside from the bottom edge, and how far it reaches (30%; more drops the label below AA) |
| `action-depth-sheen` | Thin white sheen over the top half |
| `action-depth-edge`, `action-depth-rim` | Lit 1px top edge; inset rim (`box-shadow`) |
| `action-depth-text` | Label |
| `action-depth-fill` | Ready-made `background-image`: glow plus body |
| `shadow-action-depth`, `shadow-action-depth-hover` | Contact shadow plus same-hue glow underneath |

```css
.button {
  background-image: var(--brand-action-depth-fill);
  box-shadow: var(--brand-shadow-action-depth);
  color: var(--brand-action-depth-text);
}
.button:hover { box-shadow: var(--brand-shadow-action-depth-hover); }
/* sheen: a ::after layer of radial-gradient(150% 100% at 50% 0%, var(--brand-action-depth-sheen), transparent) over the top half */
```

**Other actions:** `action-ink`, `action-ink-hover`, `action-ink-text` (ink button; turns light on dark pages); `whatsapp`, `whatsapp-hover`, `whatsapp-highlight`, `whatsapp-text`. The solid button keeps `accent` / `accent-hover` / `accent-text`.

**Offer levels** for `sky`, `blue`, `navy`, `pearl`, `obsidian`. `mark` is the flat identity colour of each level. The meanings match `@brandcloud/ui`'s `button.css`:

| Role | Use |
|---|---|
| `level-<L>-highlight` | Top stop of a level button or tile |
| `level-<L>-base` | Bottom stop, and the fill of a solid level button |
| `level-<L>-deep` | Contact shadow and rim. Never a text background |
| `level-<L>-halo` | Soft same-hue glow underneath |
| `level-<L>-text` | Label on highlight, base and hover (AA checked on all three) |
| `level-<L>-hover` | Solid level button hover fill |
| `level-<L>-mark` | Flat identity colour for offer marks, dots and rules |
| `level-<L>-ink` | Level-coloured text on canvas or surface |
| `level-<L>-fill` | Ready-made `linear-gradient(highlight, base)` |

**Button sizes:** `action-height-sm`, `action-height-md`, `action-height-lg` (default 36/44/52px). A brand can override heights and `radius-sm` in its file.

**Status text:** `status-warning-text` is a darker warning for text, AA on `canvas` and on `status-warning-subtle` at small sizes (the `status-warning` fill colour is not).

**Type:** `font-display`, `font-body`, `font-sans`, `font-mono`; marketing scale `font-size-display`, `font-size-h1`, `font-size-h2`, `font-size-h3`, `font-size-lead` (fluid `clamp()` values); product scale `font-size-{caption 11px, meta 12px, body-sm 13px, body 14px, section 16px, subtitle 18px, title 20px, stat 24px, hero 30px}`; `font-weight-*`; `letter-spacing-{normal, caps, tight}` (tight only at 20px and above).

`font-size-stat` is the 24px stat size. It was briefly called `font-size-display` in unreleased U01 work; `font-size-display` is now the marketing display headline.

**Layout:** `section-space-y` (vertical padding of a marketing section), `content`, `content-max`, `content-narrow`, `spacing-*`, `radius-*`, `shadow-*`, `z-index-*`, `breakpoint-{sm 600px, md 760px, lg 1100px, xl 1440px}` (custom properties cannot be used in media queries; TypeScript reads `semantic["breakpoint-md"]`).

### Gradients: what is allowed

Gradients are welcome when they model real light on a physical object, never the "AI" look.

- Allowed: single-hue tonal gradients (lighter top, deeper bottom, a thin sheen, a same-hue halo) on buttons, offer level tiles and occasionally one brand-colour section. Always through the tokens above.
- Never: violet to pink or cyan, rainbow or mesh backgrounds, gradient text, glow blobs behind heroes, gradient borders on every card, glass behind text, hard-coded gradient hex in components.

The build refuses any brand whose depth, level or WhatsApp stops span more than 40 degrees of hue, and `brand-ui-lint` flags the same in code.

## Accessibility checks

The build fails when any required text pair in any brand or mode is below WCAG 2.2 AA (4.5:1): body, muted and subtle text on canvas and surfaces, accent as link text, every button label on its fill (including the depth button's worst pixel under the glow and sheen at 44, 48 and 56px heights), level text on highlight, base and hover, level ink on canvas, warning text on its tint, inverse text. Status colours and the 3:1 non-text targets (focus, `border-strong`) are reported as advisories in `dist/contrast-report.json`.

The depth button check models the button as rendered: a top-to-bottom body gradient, a glow rising from the bottom edge and a thin sheen. It measures the label against its worst pixel at each height. A glow that reaches too far up the button drops the label below AA, which is why `action-depth-glow-reach` stays at 30%.

## Tailwind v4

```css
@import "tailwindcss";
@import "@brandcloud/tokens/css";
@import "@brandcloud/tokens/themes.css";
@import "@brandcloud/tokens/tailwind.css";
```

The layer is `@theme inline`, so utilities read `--brand-*` where they are used and re-theme with `data-brand` or `data-theme` on any element.

| Tokens | Utilities |
|---|---|
| colour roles | `bg-canvas`, `text-text-muted`, `border-border`, `bg-action-ink`, `bg-whatsapp`, `text-level-navy-ink` |
| shadows | `shadow-action-depth`, `hover:shadow-action-depth-hover`, `shadow-popover` |
| type | `font-display`, `font-body`, `text-display`, `text-h1`, `text-lead`, `text-body`, `tracking-tight` |
| layout | `py-section`, `h-action-md`, `max-w-content-max`, `max-w-content-narrow`, `p-4`, `rounded-control` |
| gradients | `bg-action-depth`, `bg-level-sky`, `bg-level-blue`, `bg-level-navy`, `bg-level-pearl`, `bg-level-obsidian` |

Breakpoints and z-index layers stay CSS-variable only.

## shadcn/ui

```css
@import "tailwindcss";
@import "@brandcloud/tokens/css";
@import "@brandcloud/tokens/themes.css";
@import "@brandcloud/tokens/tailwind.css";
@import "@brandcloud/tokens/shadcn.css"; /* last */
```

Stock shadcn components then inherit the brand: `--background` is `canvas`, `--primary` is `accent`, `--muted` is `surface-muted`, `--accent` is `surface-interactive`, `--destructive` is `danger`, `--input` is `border-strong`, `--ring` is `focus`, `--radius` is `radius-control`, plus `--card*`, `--popover*`, `--chart-1` to `--chart-5` and every `--sidebar-*` variable. The variables are re-declared on every `[data-theme]` and `[data-brand]` element, so they follow nested brands too.

When `shadcn.css` is loaded, the Tailwind names follow shadcn's meaning: `bg-accent` is the hover surface, not the brand accent. Use `bg-primary` for the brand colour.

## Making a brand

```sh
node packages/tokens/scripts/make-brand.mjs --name acme --label "Acme Roofing" \
  --accent "#0f766e" --ink "#111827" --paper "#fbfaf7" \
  --font-body "Inter, system-ui, sans-serif" --font-display "Fraunces, Georgia, serif"
# or: --input brief.json (same keys); --dry-run; --report report.json; --appearance solid|depth
```

It derives every role for light and dark from those inputs (surfaces from the paper, text from the ink with AA enforced, accent states, depth button, ink button, inverse sections), prints a pass or fail line for every required contrast pair and writes `packages/tokens/brands/acme.json`. It exits 1 and writes nothing when a required pair fails AA (`--force` writes anyway for review; the build will still refuse it). A light accent such as yellow cannot be link text on white: give it `overrides.light.accent`, or choose a deeper accent.

The brand file stays small and holds the inputs plus optional `overrides.shared`, `overrides.light` and `overrides.dark` for exact values (see `brands/docs.json`). After adding a brand, add its `./brands/<name>.css` entry to `package.json` exports (a test checks this) and rebuild.

## UI lint for any repository

```sh
pnpm exec brand-ui-lint                 # check against the baseline
pnpm exec brand-ui-lint --update-baseline
```

`ui-lint.config.json` in the project root:

```json
{
  "include": ["src"],
  "exclude": ["src/legacy"],
  "tokenFiles": ["src/styles/brand.css"],
  "baseline": "ui-lint-baseline.json",
  "rules": { "inline-style": false, "long-line": { "max": 200 } },
  "tokens": { "brand": "harbour", "mode": "light" }
}
```

Rules: `raw-colour`, `inline-style`, `long-line`, `raw-gradient` (gradient with hard-coded colours, or Tailwind palette stops such as `from-pink-500`), `ai-gradient` (stops spanning more than 40 degrees of hue, including `var(--brand-*)` stops when `tokens` is set), `gradient-text` (`background-clip: text`, `bg-clip-text`). Existing violations go in a baseline that may only shrink. One documented exception: `ui-lint-allow <rule>: <reason>` on the line or the line above.

## Operator mode

`[data-theme=\"operator\"]` in `themes.css` is a mode for dense product screens: Instrument Sans, warm neutral shell, white work surfaces and black primary actions. It is contrast-checked at build time like every other mode.

## Checks

```sh
pnpm --filter @brandcloud/tokens build      # writes dist, fails on any AA or gradient-hue error
pnpm --filter @brandcloud/tokens test
node packages/tokens/scripts/check-cascade.mjs   # browser check of data-brand/data-theme nesting (needs Playwright Chromium)
```
